## 0. 前置扫盲：什么是“表征”？m / z / s 分别是什么？

**表征（representation）** = 网络内部对某样东西的“数值化理解”：一个张量，**每个格子是一个向量**，向量的每一维都是网络自己学出来的特征（不是人手工设计的）。AlphaFold 内部有三张这样的表，后面所有模块都围绕它们工作：

![[三种表征.png]]

| 表征               | 形状               | 每格的含义               | 角色                |
| ---------------- | ---------------- | ------------------- | ----------------- |
| **MSA 表征 m**     | (S, R, 256)      | 某条序列某位置残基的理解（含进化语境） | **证据轨道**          |
| **pair 表征 z**    | (R, R, 128)      | 残基 i 与 j 之间关系的理解    | **结论轨道**（结构假设的载体） |
| **single 表征 s**  | (R, 384)         | 目标蛋白某残基的综合理解（无物种维）  | 结构模块的工作台          |
| （Extra MSA 表征 e） | (S_extra, R, 64) | 同 m，装海量序列           | 旁路专用，见 §5         |

六个要点：

1. **为什么必须要有 z**：结构预测的核心问题是“哪些残基对在空间上接触”——这是**两两关系**，天然需要一个 R×R 的容器来存。z[i,j] 就是“网络目前对 i、j 关系的全部理解”，训练好的模型里它的终态 ≈ 接触概率/距离分布。所以 z 是**结构假设的载体**：48 块 Evoformer 本质上是在反复精炼这张表。
2. **m 与 z 的分工**：m 是“证据轨道”（每条序列每个位置一份档案，装着进化信息），z 是“结论轨道”（每对残基一份档案，装着几何关系）。Evoformer 块 = 两条轨道各自精炼 + 一次交换（§1.1 的图）。
3. **这些张量从哪来**：第 4 课特征提取产出原始特征（氨基酸 one-hot、MSA、deletion 计数等），第 6 课 `feature_embedding/input_embedder.py` 的 InputEmbedder 把它们嵌入成 m、z 的初始值（其中 `target_feat` = 目标序列每个残基的 one-hot 氨基酸类型，21 类）；之后被 48 块反复更新。**s 由 Evoformer 返回**：`evoformer.py:123` 把 m 的**第一条序列**（目标/查询序列，即 `m[..., 0, :, :]`）过线性层得到——不是末条。
4. **不强制对称**：z[i,j] 与 z[j,i] 可以不同——i→j 和 j→i 的关系有方向性（比如相对位置）。维度数字（256/128/384/64）就是 c_m / c_z / c_s / c_e 这几个超参。
5. **z 不是注意力，是注意力加工的“工件”**：注意力是运算（动词），z 是张量（名词）。z 在 Evoformer 里有三种角色——**被读**（投影成 bias 喂给行注意力和三角注意力；这就是它总出现在注意力公式里、容易被误读成“z 就是注意力”的原因）、**被写**（外积均值 m→z、三角乘法/三角注意力、pair transition 反复更新它）、**被读出**（结构模块的 IPA 从它读接触关系）。类比：z 是传送带上的工件，注意力是工序——工序会拿起工件看一眼（作 bias）也会加工它，但工件不是工序造出来的。
6. **“作为输入”的含义与 z 的三层来源**：图里 z 画成输入，指的是**块与块之间的状态流**（残差流，类似 ResNet 的 feature map、RNN 的 hidden state）——每块 `z 进 → 更新后的 z 出`，不是用户从外面输入的东西。它的来源有三层：**① 初始值**来自输入嵌入（本 repo `input_embedder.py`：`linear_relpos` 把 $|i-j|$ 的相对位置 one-hot 编成 z，加上 `linear_tf_z_i/j` 处理 target_feat——i、j 各一个线性层，这也是 z 不强制对称的体现；完整 AF2 还有模板嵌入，本课程简化）；**② 每轮 recycling** 由 RecyclingEmbedder 把上一轮输出（坐标、pLDDT、z 自身）注回；**③ 前向过程中**被 Extra MSA 与主 Evoformer 的外积均值和三角运算不断写入共进化证据——z 从“只知道序列距离”逐步变成“知道空间接触”。

> [!question] 最关键的一问：z 里既然存着 R×R 的关系，那还要 attention 干嘛？
> 因为 **z 里没有答案**。初始 z 是一张近乎空白的登记表：relpos 只记录“序列上相隔多远”（i−j 的索引差），这是**序列距离**，不是**空间距离**——序列上隔 17 个残基的两点，空间上可能贴脸也可能隔 50 Å；target_feat 只知道氨基酸类型。初始 z 不知道任何“谁接触谁”。
>
> z 的几何内容全部是**算出来的**：训练教给网络“什么样的 MSA 模式意味着接触”（共进化→接触的规律，压缩在权重里），推理时行/列注意力、外积均值、三角运算把这套规律逐块应用到眼前这个蛋白上——**这些算子正是生产 z 的方式**。48 块跑完，z 从“空白登记表”变成“带接触假设的关系图”，结构模块再把假设翻译成坐标。所以 attention 不是“知道答案后的重复劳动”，而是**从不知道走向知道的唯一计算路径**。佐证：AF2 有一个 distogram 输出头，直接从 z 的终态读出残基对距离分布——“知道 R×R 距离”是**输出**，从来不是输入。

## 1. 全景导览：AlphaFold 到底用了几种注意力？

**5 种配方**。前 4 种全是同一个 `MultiHeadAttention` 类换配置，只有 IPA（算法 22）是几何变体。它们分布在这个主干上：

![[AF2 串行管线.png]]

### 1.1 先看清边界与顺序：Extra MSA 是上游预处理器，不是 Evoformer

读图认三个色块：**橙 = 阶段① Extra MSA Stack（4 块）**、**蓝 = 阶段② 主 Evoformer（48 块）**、**绿 = 阶段③ 结构模块**。只有蓝色叫 Evoformer。

执行顺序是**串行**的：① 先跑（吃 e，把上万条序列的共进化证据便宜地写进 z，然后 e 和它一起退场，`model.py` 里 `del e`）；② 后跑（吃 m + 已被①加料的 z）；③ 最后出坐标。说①和②“像”，是指①**复用同款模块但砍配置**（global 列注意力、窄头 c=8、只 4 块）——是“便宜版同款预处理器”，不是同一东西跑两遍，也不是并行分支。

**一个 Evoformer 块 = 双轨 + 一次跨轨交换**（蓝框内两条泳道）：

- **MSA 轨**（蓝框上盒，处理 m）：①行注意力 → ②列注意力 → ③transition → ④外积均值
- **pair 轨**（蓝框下盒，处理 z）：⑤三角乘法 → ⑥三角注意力 → ⑦transition
- **跨轨交换**（蓝框内两条橙箭头）：④把 m 汇成残基对写进 z（m→z）；z 又作 bias 回灌①（z→m）。这两条线就是“双轨道”名字的由来，也是共进化证据进出的唯一通道。

所以 Evoformer 的本质是“**两个表征互相喂养的迭代器**”：MSA 轨从进化证据里提炼，pair 轨把结果打磨成自洽的残基对关系图，48 块反复跑。Extra MSA Stack 是它前面的便宜版预处理器（复用同款模块但砍配置），结构模块是它后面的几何解码器（IPA）——三者接力，只有中间的双轨迭代器叫 Evoformer。

### 1.2 一个 Evoformer 块里的完整接线（第 5 课你会亲手写）

```python
# EvoformerBlock.forward（evoformer.py:56-65）
m = m + self.dropout_rowwise_m(self.msa_att_row(m, z))  # ① 行注意力，带 z bias，p=0.15 dropout
m = m + self.msa_att_col(m)                             # ② 列注意力
m = m + self.msa_transition(m)                          # ③ MLP（非注意力）

z = z + self.outer_product_mean(m)                      # ④ 外积均值：m 的信息写进 z

# PairStack.forward（pair_stack.py:281-285）
z = z + self.dropout_rowwise(self.tri_mul_out(z))       # ⑤ 三角乘法 out，p=0.25
z = z + self.dropout_rowwise(self.tri_mul_in(z))        #    三角乘法 in
z = z + self.dropout_rowwise(self.tri_att_start(z))     # ⑥ 三角注意力 start
z = z + self.dropout_columnwise(self.tri_att_end(z))    #    三角注意力 end
z = z + self.pair_transition(z)                         # ⑦ MLP（非注意力）
```

所有更新都是**残差式**的（`x = x + ...`）：注意力只负责“提出修改建议”，原表征始终保留。这就是为什么堆 48 块也不会信息丢失。

### 1.3 汇总表

> [!warning] “行/列注意力”的“行/列”指注意力发生在哪条线内部，不是“对行/列做注意力”
> 行注意力 = 在表的**一行内部**（一条序列内）让残基互相关注 → 沿**残基轴 R** 移动（`attn_dim=-2`）；列注意力 = 在表的**一列内部**（一个残基位置上）让序列互相关注 → 沿**序列轴 S** 移动（`attn_dim=-3`）。最易混的点：一列确实**对应**一个残基位置，但列注意力是**固定**这个残基、在列内**沿序列**移动——残基是“我在哪一列”的索引，不是注意力移动的轴。移动方向（softmax 展开的那根轴）才是表中的“注意力轴”。

```text
            残基1  残基2  残基3        ← 每"列" = 一个残基位置
序列1(人)  [  →    →    →  ]   行注意力：一行内部，沿残基移动
序列2(鼠)  [  ·    ·    ·  ]
序列3(鱼)  [  ·    ·    ·  ]
              ↓    ↓    ↓     列注意力：一列内部，沿序列移动
```

| #   | 算法    | repo 类                      | 作用张量              | 注意力轴    | 头配置            | bias 来源         | 门控      | 一句话                   |
| --- | ----- | --------------------------- | ----------------- | ------- | -------------- | --------------- | ------- | --------------------- |
| ①   | 7     | MSARowAttentionWithPairBias | m (S, R, 256)     | 残基轴 R   | 8 头×32         | **z 投影**（128→8） | ✓       | 序列内残基互相关注，被 pair 关系引导 |
| ②   | 8     | MSAColumnAttention          | m                 | 序列轴 S   | 8 头×32         | 无               | ✓       | 同一位置跨序列“对答案”          |
| ⑥   | 13/14 | TriangleAttention           | **z** (R, R, 128) | 两个方向各一遍 | 4 头×32         | **z 投影**（128→4） | ✓       | 维护残基对的三角一致性           |
| 旁   | 19    | MSAColumnGlobalAttention    | e（大 S, R, 64）     | 序列轴 S   | 8 头×8（K/V 共享）  | 无               | ✓       | 巨型 MSA 的廉价列总结         |
| 顶   | 22    | InvariantPointAttention     | s (R, 384) + z    | 残基轴 R   | 12 头×16 + 3D 点 | z 进 z 出         | ✗（改用 γ） | 几何感知的残基注意力            |

## 2. 算法 7：行注意力——MSA 的“上下文理解”，双轨道交流的入口

**它在哪**：每个 Evoformer 块的第一步（汇总表①）。作用于 MSA 表征 m，让**每条序列内部的残基互相交换信息**——S 条序列各自独立做一遍，彼此不交流（那是列注意力的活）。

**怎么构造**（`msa_stack.py:5`）：
```python
self.layer_norm_m = nn.LayerNorm(c_m)
self.layer_norm_z = nn.LayerNorm(c_z)
self.linear_z = nn.Linear(c_z, N_head, bias=False)   # z → 每头一个 bias 通道
self.mha = MultiHeadAttention(c_m, c, N_head, attn_dim=-2, gated=True)
```

**形状怎么流**（S 条序列、R 个残基）：
```text
m (S, R, 256) ──LN──> mha 的 x
z (R, R, 128) ──LN──> linear_z──> b (R, R, 8) ──moveaxis──> (8, R, R)
打分 = softmax( q·k/√c + b[头] )     ← z 在这里进来！
输出 (S, R, 256)，残差加回 m
```
**三个细节**：

1. bias 是 z 过一个 `c_z → N_head` 的线性层（无 bias）来的——**每头一个通道**，8 个头各自拿到对同一对残基的 8 种不同“关系读数”。
2. 这是双轨道交流的 **pair → MSA 方向**：两两残基的空间/共进化信息直接调制“残基 i 该关注残基 j 吗”。反向（MSA → pair）由外积均值负责。
3. z 进来之前也要过 LayerNorm（`layer_norm_z`）——两种表征的数值尺度不同。

**直觉**：像 Transformer 对一句话做 self-attention，但每一步打分都被一个“关系场”引导：如果 z 认为 i、j 在空间上靠近，i 对 j 的注意力权重自然调高。MSA 通道于是开始“知道”几何。

### 2.1 pair bias 三问：作用？来源？梯度？

**① 作用是什么？** 给每对 (i, j) 的注意力打分注入一个“关系先验”。普通打分 `q_i·k_j/√c` 只衡量**内容匹配度**；加上 bias 后：
```text
打分(i→j) = q_i·k_j/√c + bias_ij        bias_ij = linear_z(z[i,j]) 的第 h 通道
```
如果 z 认为“i 和 j 有关系（可能在 3D 接触）”，bias 抬高 i→j 的分数 → softmax 后 j 的信息大量流入 i 的表示。效果：**当前的结构假设（z）直接指挥 MSA 该怎么读**。典型循环：外积均值从共进化中发现“37-54 疑似接触” → 写进 z → 下一块 bias 抬高 37→54 的注意力 → 54 的上下文流入 37 → 表示更丰富 → 外积均值提炼出更强的证据。**正反馈循环**（受残差连接和 softmax 稳住）。
**② 它是怎么来的？** 分两层。**z 本体的来源**（见 §0）：初始 = 输入嵌入（relpos 相对位置 + target_feat）→ 被 Extra MSA 的外积均值、每块 Evoformer 的外积均值（m→z）和三角运算（z→z）不断精炼。**bias 的构造**（每块开头三行，`msa_stack.py`）：
```python
b = self.linear_z(self.layer_norm_z(z))   # (R, R, 128) → (R, R, 8)：每头一个通道，无 bias 线性层
b = b.moveaxis(-1, -3)                    # (R, R, 8) → (8, R, R)，对齐注意力期望的轴序
out = self.mha(m, bias=b)                 # 进入 MHA 后再由广播代码（上篇 §3.5）补 1 摊到 S
```
注意：**z 本体没有被修改**——linear_z 只是“读取”它，产出一份 8 通道的打分偏置；8 个头各拿一份对同一残基对不同侧面的“关系读数”。
**③ 是否参与梯度回传？——完全参与，而且是这条设计的关键路径。** 梯度链完整可追：
```text
Loss → attention 输出 → softmax → 打分 → 拆成两份：
                                      ├→ q·k 路径（常规注意力梯度）
                                      └→ bias = linear_z(LN(z)) 路径：
                                            ├→ linear_z 的权重 ✓（读取方式可学习）
                                            └→ z ✓（穿过 linear_z 流回 z）→ OPM / 三角运算 / 初始嵌入
```
`a = a + b` 是加法，梯度原样分流；`linear_z`、LayerNorm 全部可微，没有任何 detach。所以**损失函数会通过“attention 有没有用好这份 bias”来教育 z 的生产者**：bias 抬错了关注 → loss 变大 → 梯度同时修正 z 的产生方式（OPM、三角运算的权重）和读取方式（linear_z 的权重）。这就是“pair bias 注入”的精髓——它不只是把信息加进注意力，还**建立了一条从损失直达 z 生产者的教学通路**。z 因此不是手工特征，而是被端到端训练出来的可学习表征。对比反例：如果 bias 是 detach 的手工常数，梯度到 bias 就断了，z 的生产者收不到任何反馈。

> 精确化：**z 本身不是参数，是梯度通路上的中间激活**——学习的是生产者（初始嵌入、OPM、三角运算）与消费者（linear_z、IPA 读出层）的权重，z 是把梯度导回去的“导线”。且流经 z 的梯度是**多路汇合**的：块内的 bias / OPM / 三角路径各回各的，跨块看当前 z 还会被后续 47 块反复使用，所有下游梯度**累加**回传——所以第 1 块的“空白登记表”也能被训练好：它收到了全部 48 块使用经验的综合反馈（recycling 开启时还叠加上一轮的路径）。

**消费者/生产者再强调**（呼应上篇 §4.1）：行注意力是 z 的**消费者**；z 的**生产者**是外积均值和三角运算。bias 通道就是两者之间的桥梁。
## 3. 算法 8：列注意力——进化轴上的“对答案”

**它在哪**：每块第二步（汇总表②）。同样作用于 m，但沿**序列轴 S**。

**怎么构造**（`msa_stack.py:66`）：`LN(m)` + `MultiHeadAttention(256, 32, 8, attn_dim=-3, gated=True)`——**没有 bias**。

**为什么没有 bias**：z 是 R×R 的（残基对），列注意力的打分是 S×S 的（序列对），尺寸对不上——AlphaFold 也没有为“序列对”建表征。所以列注意力是纯 self-attention + 门控。

**直觉**：同一个残基位置，进化树不同分支的物种给出了不同氨基酸——列注意力让这些“答案”互相交流。行、列配合：行注意力沿**空间轴**理解结构语境，列注意力沿**进化轴**收集统计证据。
### 3.1 为什么非有列注意力不可：一条序列只提供一个样本

关键统计事实：**共进化证据是“跨序列”的相关性，而单条序列在每个位置上只贡献一个样本。**

举例——4 条序列，关注两个位置：
| 序列 | 位置 37 | 位置 54 |
| --- | --- | --- |
| 序列 1 | L | V |
| 序列 2 | L | V |
| 序列 3 | S | T |
| 序列 4 | S | T |

单看任何一条序列，“37=L 配 54=V”只是孤立事实；单看每一列，37“有时 L 有时 S”、54“有时 V 有时 T”也只是随缘变异。**但把 4 行并排放**：L↔V 和 S↔T 严格锁定——这两个位置在**协同突变**（compensatory mutation）。生物学解释：它们在 3D 结构里相互接触，一个位置突变后另一个必须补偿，否则蛋白折叠报废。所以“哪两列在协同变异”直接指向“哪些残基对在空间上接触”——这是结构预测能从序列出发的最硬的证据之一。

要捕捉这种“列与列的相关性”，只有沿序列轴交流才做得到。Evoformer 里的分工链条是：

1. **列注意力**先把“整列的分布”注入每个位置的表示——让位置 37 知道“这个位置上大家都进化成了什么”；
2. **外积均值**（算法 10）对位置对做跨序列平均，把“哪两列在协同变异”沉淀进 pair 表征 z；
3. z 记下“37 和 54 协同突变” → 结构模块据此假设它们在 3D 里接触。

反过来说，**如果没有列注意力**：每条序列在 Evoformer 里各自为政，模型退化成“每行独立预测”，共进化证据全部流失——MSA 拼成一张大表就白拼了，不如只喂一条序列。

**三者分工一句话**：行注意力让每条序列读懂自己（空间语境），列注意力让所有序列互相对答案（进化统计），外积均值把对出的答案写成残基对的证据（沉淀进 z）。

**问卷类比（把上篇 §4.1 的提醒展开）**：把 MSA 当成问卷——每条序列是一份答卷（样本），每个位置是一道题（变量）。整条证据链四步各司其职：

1. **列注意力·备料**：让每道题看到“所有答卷上这题的答案分布”（把整列信息注入该位置的表示）；
2. **外积均值·提炼**：算出哪两道题的答案总在联动（列与列的协变 → 残基对关系）；
3. **z·存证**：把“37 和 54 协同突变”记档进 pair 表征；
4. **结构模块·按证折叠**：把有联动记录的位置对放进 3D 同一邻域，作为折叠的依据。

注意全程找的都是“**题与题（位置与位置）的关联**”，不是“卷与卷（序列与序列）的相似”——序列只是提供样本量，产出永远是残基对关系。

> [!question] 参与列注意力的序列必须是同源的吗？长度不一样怎么办？
> **必须同源**——这不是列注意力的额外要求，而是 MSA 的定义：MSA 天生是“同一目标蛋白的同源序列对齐表”（上游同源搜索只召回 homologs）。因为同源，第 c 列在所有行对应**同一个祖先位置**，“同一位置跨物种对照”才有语义；混入无关蛋白则第 c 列在各行含义不同，算出的“协变”是噪声。**长度差异由对齐在上游解决**：插入 gap（-）把所有行垫成等长 R、同源位置对齐到同列，gap 是字母表合法成员；列注意力从不面对长度不一的原始序列。同源还有“度”的 sweet spot：太近无变异信号、太远对齐不可靠——搜索打分+聚类那步就是在控制这个度。类比：MSA = 同一句话的多语言翻译，列注意力 = 比较同一词位在各语言的渲染；混入无关句子则比较是噪声。

> [!warning] 上面四步是证据的逻辑流向，不是单个 Evoformer 块内的执行顺序！
> 块内的真实顺序是**先行注意力、后列注意力**（`evoformer.py:56-57`），外积均值在两者之后。逻辑循环靠 **48 块迭代**完成：块 k 的列混合 → 块 k 尾部外积均值写 z → **块 k+1 开头**的行注意力消费 z。为什么块内行在前？两条经验理由：① z 在上一块尾部刚被大更新，块首的行注意力让最新结构假设立刻引导本轮阅读；② 先“带先验各自读链”再“家族混合”，避免共识过早抹平序列差异。但块内顺序属经验选择——反转大概率也能训，重要的是双向交流在 48 轮迭代中反复发生，而非单块内的先后。

> [!question] 常见疑问：列注意力不对 R 做，那“位置和位置的相关性”是谁算的？
> 两点澄清。第一，Evoformer **有**对 R 的注意力——行注意力（算法 7）就是沿残基轴的，每个块行、列两个都做。第二，“位置对相关性”的主力计算者**不是注意力，是外积均值**（算法 10）：`einsum('...sic,...sjd->...ijcd')` 对每一对位置 (i, j) 做跨序列的外积平均——若两列取值联动（L↔V、S↔T），平均后 z[i,j] 浮现一致模式；若各自随机变异则互相抵消。协方差分析是确定性统计，不需要注意力。分工：**列注意力备料 → 外积均值算位置对相关写进 z → 行注意力用 z 作 bias 消费它 → 三角注意力精炼 z 的自洽**。注意力只是 Evoformer 工具箱的手段之一；终点是填出 R×R 的接触关系图加坐标。

> [!question] 连环追问一：batch 开大不就能“看见”位置相关性了吗？普通 attention 又怎么知道句内 token 的相关性？
> 两个问题共用一个答案——“相关”有两种，机制完全不同：**① 内容相关**（“这两个向量的特征匹不匹配”）：query·key 即时算出，是两个内容向量的函数，一个序列/一句话内部即可完成——普通 attention 和行注意力做的就是它。**② 协变相关**（“这两列跨物种是否联动”）：分布层面的统计量，必须有多行样本，由列方向机制 + 外积均值计算。batch 开大帮不上②：batch 元素是**不同的蛋白**（相当于不同的问卷），既互不通信，也不提供“本蛋白 37-54 是否接触”的证据；训练能学到通用先验，但替代不了实例证据——实证是 S=1 时 AlphaFold 准确率大跌。NLP 里基本只有①的需求（语言的相关性是内容性的），所以普通 Transformer 只沿 token 轴做就够；蛋白质①②都要（链内语境靠①，接触证据靠②，z 把②喂给①），这才是双轨道设计的理由。

## 4. 算法 13/14：三角注意力——在 pair 矩阵上维持几何一致性

**它在哪**：PairStack 的主力（汇总表⑥）。前几种注意力都作用在 m 上，**这一种直接作用在 pair 表征 z (R, R, 128) 上**——z 的每个格子 z[i,j] 是“残基 i 和 j 的关系”。

**为什么叫三角**：几何上有个硬约束——如果 i-j 关系强、j-k 关系强，那么 i-k 也应该强（三角形两边推出第三边）。三角乘法用乘法更新这一性质，三角注意力用注意力更新：让“共享一个顶点的那些残基对”互相看一眼，交换一致性信息。（三角乘法是算法 11/12，**不是注意力**，本文不展开，第 5 课 `pair_stack.py` 会亲手写。）

> [!info] 先回答“它是不是注意力”：是，真·注意力
> 判别标准只有一条：有没有 QKV 投影 + softmax(QKᵀ/√c + bias) + 加权求和 V。三角注意力全有——内部就是调用 `MultiHeadAttention` 跑标准公式。“三角”不是新机制，而是三个**配置**让标准注意力获得三角传递的含义：① 跑在 pair 表征 z 上（数据本身是残基对关系）；② 选哪根轴（固定一个顶点、沿另一索引移动 = 共享顶点的边互相看）；③ bias 来自 z 自己（score(j→k) 的 bias 用 z[j,k] = 第三边）。所以“MHA 里没有三角逻辑”（引擎通用）与“三角注意力是注意力”（配置让它做三角传递）不矛盾。行/列/global/三角都是同一引擎的不同配置，都**是**注意力；只有三角**乘法**（11/12，无 softmax/QKV）不是。

**怎么构造**（`pair_stack.py:90`）：
```python
self.layer_norm = nn.LayerNorm(c_z)
attn_dim = -2 if node_type == 'starting_node' else -3   # 两个方向
self.mha = MultiHeadAttention(c_z, c, N_head, attn_dim, gated=True)   # 128→4头×32
self.linear = nn.Linear(c_z, N_head, bias=False)         # z 自己投影出 bias
```

**它到底在算什么（starting node 逐步）**：固定起点 i，取 z 的第 i 行 {z[i,1..R]}（“i 与每个残基的关系”）。在这 R 个元素间做注意力：z[i,j] 作 query，attend 同行的 z[i,k]；score(j→k) 的 bias 来自 **z[j,k]**（j 与 k 的直接关系 = 三角形第三边）。于是“i 对 j 的关系”被“i 对 k 的关系”按“j-k 多相关”加权更新——**i-j ← i-k ⊗ k-j**，正是第三边传递；沿 k 聚合后残差更新 z[i,j]。

**迷你例子（R=3，starting node，固定 i=1；记 query 下标 j、key 下标 k）**：更新 z[1,2]（即 j=2）。query = z[1,2]；keys/values = **整行** {z[1,1], z[1,2], z[1,3]}（k=1,2,3，含矩阵对角项 z[1,1] 和 k=j 时 query 自身项 z[1,2]）；query 与这三个 key **各打一次分**——s(2→1)、s(2→2)、s(2→3) 一个不少（三条公式见图），加权求和也混三个 value v(z[1,1])、v(z[1,2])、v(z[1,3])。**bias 不是一个数，而是一整条矩阵**：三个打分 s(2→k) 各配各的 bias b[2,k] ← z[2,k]（starting node 不转置，直接用 z[j,k]）——s(2→1) 配 z[2,1]、s(2→2) 配 z[2,2]、s(2→3) 配 z[2,3]。例子聚焦 score(j=2→k=3) 的 bias = **z[2,3]**（第三边：j 与 k 的直接关系），只因它是三个里唯一凑成三顶点三角形的；z[2,1]、z[2,2] 一样参与计算（见下方 ❓ 框）。若 z[2,3] 高 → softmax 给 k=3 的权重大 → z[1,2] 大量吸收 value z[1,3] → 向“与 z[1,3]、z[2,3] 一致”的方向修正（另两个打分照算，只是该情景下权重小；图中黑粗线 = 本例主角路径、灰细线 = 参与计算但非讲解重点）。三角形 (i,j,k)=(1,2,3) 的三条边 = z[1,2]（i-j，query 元素）、z[1,3]（i-k，key 元素）、z[2,3]（j-k，bias）。三条边由此互相校准。

![[三角注意力迷你例子 1.png]]

> [!question] 为什么例子里只点出 z［2,3］ 当 bias？z［2,2］、z［2,1］ 不也有吗？
> 有！**bias 不是一个数，而是一整条矩阵** b[j,k] = linear(LN(z))[j,k]，**逐元素加到整张打分矩阵上**——和行注意力（§2.1）完全同一个机制、同一段 `mha.py` 广播代码。更新 z[1,2] 时 softmax 沿 k=1,2,3 展开，**三个打分各配各的 bias**：
>
> |k|key/value 元素|该打分的 bias|三角形 (i,j,k)=(1,2,k)|
> |---|---|---|---|
> |1|z[1,1]|b[2,1] ← z[2,1]|k=i，退化（z[2,1] 恰是被更新边 z[1,2] 的反向边）|
> |2|z[1,2]（自身）|b[2,2] ← z[2,2]|k=j，退化（对角自身项）|
> |3|z[1,3]|**b[2,3] ← z[2,3]**|**三顶点互异，真三角形 ✓**|
>
> 只点 z[2,3] 纯粹是**讲解取舍**：三个里只有它凑出三顶点互异的三角形 (1,2,3)——query 边 z[1,2]、key 边 z[1,3]、bias 边 z[2,3] 恰好围成一圈，“第三边传递”的解读才完整成立。z[2,1]、z[2,2] 照样参与计算、照样加进打分，只是 k 与 i 或 j 重合、三角形退化成一条边或一个点，几何解读平淡。通用规则一句话：**score(j→k) 的 bias 永远取 z[j,k]**，“第三边”只是 i、j、k 互异时的几何含义，公式本身不分退化与否。代码里 `b = self.linear(self.layer_norm(z))` 一次性把**整条** (R, R, N_head) bias 矩阵算好交给 MHA——不存在“只挑某一个”的步骤。

> [!question] 图里 z［1,2］ 只和 z［1,3］ 打分吗？和 z［1,1］ 呢？
> 三个都打。query z[1,2] 与行内三个 key **各算一个打分**：s(2→1) 对 z[1,1]、s(2→2) 对 z[1,2]（自身）、s(2→3) 对 z[1,3]；softmax 把**三个**打分变成**三个**和为 1 的权重，加权求和混**三个** value——输出是三者混合，不是只吸收 z[1,3]。图把 k=3 路径画黑粗、k=1,2 画灰细，纯是**视觉重点**：本例设定“z[2,3] 高 ⇒ w(2→3) 大”，主角是 k=3 路径；若换成 z[2,1] 高，主角就换成 k=1 路径（大量吸收 z[1,1]）。粗细说的是“本例谁主导”，不是“谁参与计算”。再补一层：这套“query 对整行打分”的流程对 **z 的每个格子都并行跑一遍**（共 R×R 次更新，图只展开其中一次），所以“z[1,2] 与 z[1,1] 打分”在完整计算里出现**两次、方向相反**——更新 z[1,2] 时作 s(2→1)（z[1,2] 为 query、z[1,1] 为 key），更新 z[1,1] 时作 s(1→2)（角色互换）。打分是**有方向的 query–key 有序对**，每个 query 各自对整行跑独立的 softmax。

**两个方向的区别**（这是最容易晕的地方，z 记作 z[i,j]）：

|               | starting node（算法 13）     | ending node（算法 14）            |
| ------------- | ------------------------ | ----------------------------- |
| 固定谁           | 固定**起点 i**               | 固定**终点 j**                    |
| 谁和谁交流         | 同一行 {z[i,1],…,z[i,R]} 内部 | 同一列 {z[1,j],…,z[R,j]} 内部      |
| attn_dim      | -2（沿 j）                  | -3（沿 i）                       |
| bias          | b[i,j] 直接用               | **转置后用 b[j,i]**（读数方向要和交流方向一致） |
| 同轴配置的 MSA 对应物 | 算法 7 行注意力（attn_dim=-2）   | 算法 8 列注意力（attn_dim=-3）        |

> [!question] starting / ending node 相当于在 z 上沿“行方向”和“列方向”做注意力吗？
> 基本是，而且就是设计本意：starting node `attn_dim=-2` = 沿 z 的**行方向**（固定行 i、沿列下标 j 移动，让“以 i 为共同起点的边”交流）；ending node `attn_dim=-3` = 沿 z 的**列方向**（固定列 j、沿行下标 i 移动，让“以 j 为共同终点的边”交流）——和算法 7/8 在 m 上的行/列注意力是**同一个 attn_dim 旋钮**，同一台引擎换轴。两个防混点：① 这里的行/列是 **pair 矩阵 z（R×R）** 的行列，不是 MSA 表（S×R）的行列——z 的一行 = 从残基 i 出发的所有残基对关系（出边集合），一列 = 指向残基 j 的所有关系（入边集合），starting/ending 的名字正来自“共享起点/终点”；② 一个不对称：ending node 的 bias 要**转置**（读数方向和交流方向一致），MSA 列注意力干脆没有 bias，没这个烦恼——这是“z 自己给自己作 bias”带来的独有细节。

**直觉**：starting node 相当于“以 i 为共同开头的所有三角形（i,j,k）互相通报消息”；ending node 是“以 j 为共同结尾的”。残基对没有天然顺序，所以两个方向都要做一遍，才能把三角约束传遍整张关系图。

![[为什么 z 作自己的 bias 加回 z 不是循环.png]]

> [!question] 三角注意力拿 z 自己的值作 bias 加回 z——不会“先有鸡还是先有蛋”或“左脚踩右脚”吗？
> 不会。“回加到自己”的永远是**上一刻的自己（快照）**，不是“正在算出来的值”。三层保险：
>
> 1. **快照并行更新（块内无鸡生蛋）**：`tri_att(z_in)` 里所有读取——query/key/value、bias——都指向**同一份**输入快照 z_in，输出 z_out 是全新张量。z_out[1,2] 与 z_out[2,3] 各自从 z_in 算出，**互不引用对方的新值**——像细胞自动机 / 全班按旧座位表同时换座，是同步更新，不是“改完一个人的分立刻用新分改下一个人”。代码 `z = z + self.tri_att_start(z)`（pair_stack.py）先算完右边再重新绑定名字 z——“自己引用自己”只是**同名变量的错觉**，计算图是链不是环。
> 2. **残差是地面（无左脚踩右脚）**：更新式 z_out = z_in + Δ，注意力只提修正量 Δ，旧值原封保留——左脚踩实地面（z_in）、右脚迈新步（Δ）。真“左脚踩右脚”是 z_out 只由 z_out 自己定义，那才悬空；残差连接就是那块地面。
> 3. **链条有起点（蛋先有）**：z_0 由输入嵌入器从**外部数据**（relpos + target_feat）产出，之后 z_1 = f(z_0)、…、z_48 = f(z_47) 逐块展开——有 base case 的有限步递推，不是循环定义；反向传播沿这条链展开梯度（同 BPTT 原理）。recycling 同理：有限轮，第 1 轮没有回收输入。

> 补一个细节：“把自己的值当 bias”也不严格——更新 z[1,2] 时 bias 取的是 z[2,1]、z[2,2]、z[2,3]（**别的格子**的旧值）；即便 query/key 用到 z[1,2] 自身，用的也是快照里的旧值。一句话：**名字层面的“z 喂 z”，在时间步层面是链 “z_{t+1} = f(z_t)”**；看起来像环，只是变量名被复用。

## 5. 算法 19：全局列注意力——旁路的廉价总结

机制已在《上篇》§4 讲透（query 平均 + K/V 单头共享）。这里补系统定位：

**它在哪**：Extra MSA Stack（算法 18，共 4 块）的第二步。这个旁路吃的是**上万条**的巨型 MSA（主 Evoformer 只吃几百条），目标是便宜地再榨一点进化信息。

**它的块结构**（`extra_msa_stack.py:118`）——和 EvoformerBlock 几乎一样，只有两处降配：
```python
self.msa_att_row = MSARowAttentionWithPairBias(c_e, c_z, c=8)   # 行注意力：头变窄（8×8）
self.msa_att_col = MSAColumnGlobalAttention(c_e, c_z)           # 列注意力：换成全局版（算法 19）
```
即：行注意力保留（残基轴只有几百长，S×S 的麻烦不在它），列注意力换成 global（O(S²) → O(S)），每头维度也从 32 缩到 8。整条旁路的哲学是：**信息可以粗糙，但必须便宜**。

**为什么不干脆砍掉旁路？** 上万条序列里仍有主 Evoformer 没吃到的信号（主路只喂几百条）；旁路用约 1% 的成本把它们榨出来，性价比极高——这正是“廉价层”存在的意义（呼应上篇 §4）。

**e 和 m 是什么关系？同一池同源序列的两个不相交子集。** 搜数据库得到海量同源序列（数万+）后切成两份：头部 ~512 条进主 MSA m（全价精读：48 块、精确列注意力、宽头 32），剩下的长尾进 Extra MSA e（廉价略读：4 块、global 列注意力、窄头 8）。两边都是对齐的氨基酸序列，S 只是“各自子集的条数”（S_main ≠ S_extra）。为什么切：精确列注意力 O(S²) 对长尾跑不起，但长尾扔掉可惜——折中为“头部精读 + 长尾略读”，两路的外积均值都写进同一个 z。时序上 e 的略读先发生（§1.1 串行上游），m 的精读随后，z 同时吸收两路证据。类比：精读 500 篇核心文献 + 略读 9500 篇长尾，笔记汇入同一份综述。（512/5120 为 AF2 参考配置；本 repo 不做切分，吃你喂的任何 MSA。）

> [!question] 那几百条“精读”是怎么选出来的？需要预知谁重要吗？
> **不需要预知**——用廉价代理信号启发式地选。**真实 AF2**：先按搜索打分（E-value/同源性）排序，再按**序列相似度贪心聚类**去冗余（近重复序列不提供新的共进化对比，多样性才提供），每簇选一个代表，取 top ~512 簇作主 MSA；更深更大的 BFD 搜索池截断成 extra MSA。**本 repo（第 4 课 `select_cluster_centers`）** 是教学简化：固定第 0 行（目标序列），其余**随机洗牌**取前 512 作主 MSA、剩下的进 extra——用随机代替了相似度聚类。为什么随机也够？因为共进化信号是**统计性**的：只要主 MSA 够多够多样，具体挑哪 512 条影响不大，extra 又把剩下的全部略读、信号不丢。聚类只是为了在固定预算下最大化多样性。

> [!warning] extra MSA stack 只是 z 的第一个更新者，不是唯一/主力生产者
> z 的生产者链条：z₀ 来自输入嵌入（relpos+target_feat）→ ① extra MSA stack 写入“长尾略读”证据 → ② 主 Evoformer 48 块**每块都更新 z**（外积均值 m→z + 三角乘法/三角注意力 + pair transition），这才是主力 →（recycling 注回）→ 被行/三角注意力 bias、IPA、distogram 头消费。别把 z 的功劳全记在 extra MSA 头上：extra 是第一个写 z 的，Evoformer 是写得最多的。

## 6. 算法 22：IPA——带 3D 坐标的多头注意力（第 8 课预习）

> [!question] 先说人话：这一节在解决什么问题？
> 前面 5 种注意力看的都是**特征向量**——一堆没有空间含义的数字。但结构模块的任务是输出 **3D 坐标**，而坐标数值是“随摆放变”的：同一条蛋白挪个位置、转个角度，每个原子的 (x,y,z) 全变了，结构却没变。所以结构模块需要一种**能看见几何、又不依赖摆放**的注意力。IPA（Invariant Point Attention，**不变点注意力**）就是它。名字拆开：**点** = 它真的往 3D 空间里“插点”；**不变** = 整条蛋白随便旋转平移，打分和输出完全不变。

### 6.1 三个新词汇（后面全靠它们，慢慢看）

**① 刚体变换 T——粘在每个残基身上的小坐标系。** 想象每个残基是一张办公桌：桌子有**位置**（摆在哪）和**朝向**（冲哪边），但桌子本身不变形（“刚体” = 只许平移+旋转，不许拉压）。T 就是“这张桌子在世界里的位置+朝向”，数学上是一个 4×4 矩阵（3×3 旋转 + 3 平移）。**每个残基一个 T**，结构模块全程维护；全部 T 合起来 = “目前认为整条蛋白长什么样”，最终坐标就是从 T 里读出来的。

**② 3D 点（point）——从残基上伸出的“小图钉”。** 每个残基把特征投影出几个 3D 点：每头 **4 个查询点 + 4 个关键点 + 8 个值点**。这些点**长在残基自己的小坐标系里**（桌子搬到哪它们跟到哪）；打分时先用各自的 T 把点变换到**全局坐标**再量距离（`warp_3d_point`）。

> [!warning] 别把“投影出点”误读成“残基用点表示”
> 残基的主表示仍是特征向量 s（384 维）；点是从 s **线性投影出来**的（`linear_q/k/v_points` 的输入就是 s，见 `prepare_qkv`：六路投影全吃同一个 s），每个点只有 3 维 (x,y,z)，承载的信息远少于 s。它不取代标量 QKV——打分时特征项管“像不像”、点距项管“近不近”，两套并存。点也不是真实原子坐标（N/Cα/C 主链框架是另一回事），而是网络学出来的**虚拟探针**：训练调整投影权重，让探针落在“对判断接触有用”的地方。

> [!question] “每头”的头是啥？
> 就是多头注意力（上篇 §1）里那个“头”，老概念，不是 IPA 新发明的。**头 = 切分后的一份独立并行通道**：s 的 384 维投影成 12 套独立的 q/k/v（每套 16 维，`linear_q` 输出 12×16=192 维再切开），12 套各自打分（12 个独立的 R×R 打分矩阵）、各自加权求和，最后拼接——这就是“多头”的全部含义。在 IPA 里点也按头切：`linear_q_points` 输出 12头×4点×3坐标 = 144 维，切成 12 份，**每头拿自己那份 4 个 (x,y,z)**——“每头 4+4+8”说的是**单头配额**，整个残基共 12×(4+4+8) = 192 个点。类比：12 个记者各拿同一份档案（s）独立采访，各有各的笔记视角（16 维特征）、各打各的分（独立打分矩阵）、各带各的探针（摆放由各自投影权重决定、训练各自学），最后 12 份报道拼接过 `linear_out`。多头存在的理由不变：不同头学**不同的关注模式**——IPA 里尤其直观，一个头的探针可以学“伸向主链方向看骨架接触”，另一个学“伸向侧链方向看疏水堆积”。每头 bias 也独立（`linear_b` 每头一个数），γ 也是每头一个旋钮。

**③ 不变（invariant）——量“几何”不量“坐标”。** 把整条蛋白平移/旋转（所有 T 一起变），点与点的**欧氏距离不变** → 打分不变、输出不变。网络学到的是“谁离谁近”这种几何事实，而不是“x=3.2”这种随手摆出来的坐标数值——坐标系的选取骗不了它。这就是“不变点”的含义：点参与运算，但结果不随刚体运动变。

![[IPA 直觉：小坐标系 + 3D 点 + 三项打分 + 四路输出.png]]

> [!question] 残基坐标系怎么理解？蛋白的 xyz 按什么坐标系定？所有残基共享一个坐标系吗？
> 分两层答，两层各管各的。**第一层：全局坐标系——存文件时一整个蛋白共享一个。** PDB 文件里所有原子的 (x,y,z) 写在**同一套**直角坐标系里。它哪来的？纯约定：X 射线/冷冻电镜/NMR 测结构时按仪器和晶胞摆放规定的——把整条蛋白挪 10 Å、转 30°，还是同一个蛋白。所以“蛋白在空间的绝对位置和朝向”**没有物理意义**，有意义的只有内部几何（原子间距离、键角）。 **第二层：局部坐标系——每个残基一个，结构模块发的。** 每个残基主链有 N、Cα、C 三个特征原子：**Cα 当原点、键方向定两个轴向**（本 repo 是 `create_4x4_transform(ex, ey, translation)`，完整 AF2 叫 rigid_from_3_points），拼成 4×4 的 T_i = 位置 t_i + 朝向 R_i。侧链原子、IPA 的 3D 点都定义在**自己残基的局部系**里——图钉长在自己桌上。

![[两层坐标系：全局系 × 残基局部系.png]]

**换算关系**：x_全局 = R_i · x_局部 + t_i，即 `warp_3d_point(T_i, x)`。IPA 打分时把 i、j 两家的图钉各自换到全局系再量距离；整条蛋白被旋转/平移时（训练时还故意随机做这种增广），全局坐标全变、每个 T_i 跟着变，**但点距不变**——§6.1 ③ 的“不变”机关就在这。

> 一句话：**全局系回答“整条蛋白摆在哪”（答案：无所谓），局部系回答“每个残基身上的几何长什么样”（IPA 真正关心的）。** 共享的是全局系；不共享、人手一个的是局部系 T_i。

### 6.2 打分公式：三项拼出来的（`ipa.py:173`）

还是“残基互相关注”的骨架（QKV、多头、softmax、加权求和一样不少），只是打分公式多了第三项：
```text
score(i→j) = softmax( wl · ( q·k/√c  +  bias  −  γ·(wc/2)·Σ_p ‖q点_p − k点_p‖² ) )
wl=√(1/3) 三项平均；wc=√(2/(9·n_qp)) 点距配平；γ=softplus(每头权重)，只乘点距项
```

括号里三项一项一项看：

|项|是什么|和前面的关系|
|---|---|---|
|q·k/√c|**特征匹配度**（“你像不像我”）|和普通 MHA 完全相同|
|+ bias|**pair bias**（z 投影 128→12，每头一个）|和算法 7 同一套路，这里叫 `linear_b`|
|− γ·(wc/2)·Σ_p‖q点_p − k点_p‖²|**几何接近度**：i、j 的点（经各自 T 变到全局）**同序号配对**的距离平方和（每头 4 对）|**IPA 的新货**，全篇独一份|

三个关键细节：

1. **点距项带负号**：两个残基的点靠得越近，Σ‖·‖² 越小、减得越少、分数越高——“空间接近 = 高分”。这就是注意力“看见”几何的方式。
2. **γ 只乘点距项**：γ = softplus（每头 1 个可学习权重），是每头对“几何证据信多少”的**可学习强度**（初始化 0 → 起步不偏信几何，随训练学着用）。它取代了普通 MHA 里 sigmoid 门控的角色。
3. **两个缩放常数**：wl = √(1/3) 把三项做平均（量纲不同）；wc = √(2/(9·n_qp)) 把点距项配平。bias 不除 √c 的道理见上篇 §1.3。

**怎么构造**（`ipa.py:12`，配置 N_head=12、每头 c=16、n_qp=4、n_pv=8）：

|组件|投影|干什么|
|---|---|---|
|`linear_q/k/v`|384 → 12×16（**带 bias**，和 mha.py 不同）|标量通道的 QKV|
|`linear_q/k_points`|384 → 12×4×3 / 12×4×3|每头 4 个 3D 查询/关键点|
|`linear_v_points`|384 → 12×8×3|每头 8 个 3D 值点|
|`linear_b`|128 → 12|**z 投影成 bias**（同算法 7 的套路）|
|`head_weights` + softplus|每头 1 个 γ>0|打分的**每头可学习强度**（替代门控的角色）|

### 6.3 输出四路（比普通 MHA 丰富）

softmax 的权重不只加权 value，而是**同时加权四路信息**，拼起来过 `linear_out` 变回 s：

|路|加权的是什么|备注|
|---|---|---|
|v_out|常规 value 特征向量|和普通 MHA 的输出一样|
|vp_out|**值点**（8 个/头）的坐标|加权求和后**换算回各残基自己的小坐标系**（不变性再保一次）|
|vp_out_norm|上面点向量的长度|长度天然与坐标系无关|
|pairwise_out|**pair 表征 z[i,j]**|同一套权重还对 z 做加权读出——z 在这里当 value 用|

四路拼接（12×16 + 12×24 + 12×8 + 12×128 = 2112 维）→ `linear_out` → 更新 s。

### 6.4 它在哪：结构模块的“眼睛”（算法 20，共 8 层）

IPA 是**结构模块（算法 20）** 每层的核心，每层三件事：**IPA（看）→ 更新 s → backbone update 挪 T（算法 23）**。像雕塑：先看一眼当前形状（T 说明“残基们现在都在哪”），IPA 帮 s 判断“接下来该往哪挪”，backbone update 再把 T 挪一点点；8 层迭代把坐标从模糊挪到精确。它的输入是 s (R, 384)（取自 MSA 的**第一条**序列，见 §0）+ z + T——五种注意力里**唯一吃几何的**。

### 6.5 和普通 MHA 的对比

| 对比项 | 普通 MHA | IPA |
|---|---|---|
|打分项|q·k/√c（+外部 bias）|q·k/√c + bias **− 3D 点距**（越近分越高）|
|值通道|特征向量|特征向量 + **3D 点坐标**（另含点长、z 读出）|
|几何信息|无（除非外部喂 bias）|内建，刚体不变|
|位置感知|靠外部位置编码/偏置|自带坐标系 T|
